# ADR 0018: SSE 落后检测与快照回放恢复

- 状态：已接受。客户端游标部分由 ADR 0024 取代
- 日期：2026-10-20

## 背景

ADR 0002 规定客户端用 `after` 游标断线续传。事实事件持久化在 SQLite；token 增量只在内存中传输。事件总线是容量固定的 broadcast 通道，订阅者落后超过容量时收到 `Lagged`。此前 `agent` 只为 `Lagged` 发送 SSE 注释行，注释行不进入 `EventSource.onmessage`，客户端无法察觉事件缺失。快照（bootstrap、消息树）也没有水位，客户端无法判断快照与已应用事件的前后关系。

本决策细化 ADR 0017 的断线续传：重连时先刷新快照，并允许游标回退。

## 决策

**落后是显式事件。** `StreamEvent` 增加 `Resync` 变体，携带 `ResyncReason::Lagged { skipped }`。`agent` 在 `Lagged` 时发送该事件，然后结束该 SSE 连接。客户端因此能区分“实时”与“可能丢失事件”。

**快照携带水位。** `BootstrapResponse.maxEventId` 与 `SessionTree.maxEventId` 是快照读取事务开始时的全局最大事实事件 id。快照包含该 id 及之前的全部事实。

**游标在快照落地时回退。** 客户端只保留一个游标 `lastEventId`，取值是“已应用的最大事实事件 id”。应用快照后的游标为：尚无基线时取快照水位；已有基线时取 `min(游标, 水位)`。回退使事件流用 `after` 重放快照未覆盖的尾部。回退后客户端立即用新游标重开事件流。

**恢复流程。** 客户端在 `Resync` 事件或连接错误后重新获取 bootstrap 与当前 session 的 tree，应用两者，再用游标重开事件流。选中 session 时的 tree 快照若降低游标，客户端同样重开事件流。快照读取发生在最后已应用事件提交之后，因此快照是已应用状态的超集；回退只会重放，不会丢失。

**幂等合并。** 事实事件携带完整元数据快照，按 id 单调去重：id ≤ 游标的事件丢弃。重复与乱序因此不改变状态；回放结果等于从零构建的结果。

**增量是易失的。** token 增量不落库。断线或快照落地后，进行中的增量不再出现；run 结束的 `message_updated` 携带完整文本并覆盖增量结果，因此 assistant 文本最终一致。

## 后果

- 恢复时最多重放快照水位之后的事件；重放幂等，代价受游标回退幅度限制。
- 切换 session 时的快照可能重开事件流；连接在切换时可能短暂重建。
- 客户端不再依赖 `EventSource` 的自动重连；重连时机与游标由客户端显式控制。
- 进行中的 assistant 文本在断线或快照落地后暂时缺失，直到 run 结束。
