# ADR 0036: 压缩消息在链上，装配回溯到它为止

- 状态：已接受
- 日期：2026-10-22

## 背景

上下文超过上限时需要压缩：用一段摘要替代 transcript 的前缀。压缩结果必须可持久、可审计，并且不能把「历史」与「这次发了什么」混成一份数据。ADR 0035 已把节点正文定为内容块数组。

## 决策

**压缩消息是链上的一个节点**，`role` 为 `compaction`，正文是摘要的内容块。它的 `parent_id` 指向它替代的最后一条消息，因此被替代的历史仍是它的祖先，不被删除、不被改写。写入压缩消息时 `active_leaf` 移动到它，后续消息成为它的后代。

**装配 transcript 的规则**：从 `active_leaf` 向上回溯，遇到压缩消息即停止并把它作为首条；遇到没有父消息的节点也停止。压缩消息本身会被发送。

**压缩是原子的**：成功则整条消息一次入树；失败或中途崩溃不留痕迹，重做一次即可。压缩不属于任何 run，没有 `run_id`；它由引擎在需要时调用，也可以由用户命令调用。

**wire 身份由 provider 决定**：上游没有 `compaction` 角色。provider 可以发成一条 `user` 消息，也可以在上游支持时放进 `system`/`developer` 角色。转换规则属于 provider 的能力，写在 ADR 之外。

**多条压缩自然嵌套**：第二次压缩的输入已经包含第一条压缩的摘要，因为回溯到第一条压缩消息就停了。因此链上有多条压缩消息时不需要额外规则。

## 后果

- 历史不被压缩改写。切回压缩之前的旧分支时，回溯路径不经过压缩消息，上下文自然恢复成全量。
- 压缩不可撤销，但可以被新的压缩覆盖；「哪段被省略」可以随时从链上重算。
- 压缩失败不影响任何 run 的结局，也不需要恢复逻辑介入。
- 客户端把压缩消息当一条消息渲染，并且能看出它是摘要，而不是模型对用户说的话。
- 前缀的旧消息仍占存储，随会话增长；需要时再讨论冷数据清理，不在本节范围内。
