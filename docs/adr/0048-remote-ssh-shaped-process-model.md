# ADR 0048: 进程模型反转为 remote-ssh 形状

- 状态：已接受。取代 ADR 0001 的两个二进制划分与 ADR 0021 至 ADR 0024 的总线与分片决策
- 日期：2026-10-28

## 背景

ADR 0001 把 agent 循环与工具执行放在同一个进程，ADR 0021 再让 `hub` 成为多节点总线。结果有三处不合用：

- 会话历史按机器分散。换一台机器就要另开页面，也没有一处能读到全部历史。
- 模型密钥要配在每台机器上。谁跑工具，谁就必须知道 provider 与 key。
- 工具执行与模型调用绑在一起。用户想在笔记本上持有模型调用与全部历史，在服务器上读写文件，今天做不到。

用户要求照 VS Code Remote SSH 的形状改造：一个进程负责 agent loop，工具调用交给出工具所在机器上的代理服务，workspace 与机器绑定，两侧通过 SSH 安装与通信。

## 决策

**角色反转。** `agent`（原 `hub`）是唯一权威：agent loop、provider 调用、消息树、队列、事件与 SQLite 都在它里面，它也继续托管浏览器客户端。`executor` 是 host 上的工具执行端，只执行工具，不持有数据库。原 `agent` 二进制退役。

**命名。** 三个角色叫 `agent`、`host`、`executor`，通道叫 `link`。`hub` 与 `node` 两个词删除：前者不再汇聚任何东西，后者不再是「一台机器上的 agent 与其 SQLite」。host 的身份是名称，连接参数是一个 SSH 目标字符串，端口、密钥与跳板全部交给 `~/.ssh/config` 与 ssh-agent。

**传输。** `agent` 启动 `ssh <target> durable-executor`，两侧在标准输入输出上交换带长度前缀的 JSON 帧。远端不监听任何端口，信任边界完全落在 SSH 上。本机是一个 host，传输是直接启动 `executor` 子进程，帧协议与工具语义只有一份。

**安装。** `agent` 内嵌各平台的 `executor` 二进制，首次连接时按远端平台选择、推送并校验构建版本。版本不符时 host 状态为 `incompatible`。发布因此需要构建矩阵。

**文件系统事实只有一处判定。** workspace 注册时的路径校验、工具路径解析与四个工具的执行全部在 `executor` 内完成。`agent` 只保存结果，不重算边界。

**工具定义只有一份。** 名称、说明与 JSON Schema 留在共用的 `durable` crate：`agent` 引用它拼模型请求，`executor` 引用它做参数反序列化与校验。`agent` 只透传 JSON，不理解参数形状。

**传输有两种，帧只有一种。** 远端 host 的传输是 `ssh` 子进程，本机 host 的传输是 `executor` 子进程，两者都以标准输入输出作为 link。帧只有四种：请求、结果、取消、心跳。一次工具调用一帧请求、一帧结果；取消按请求 id 匹配；`executor` 收到取消后杀掉进程组，仍回一帧结果；心跳用于保活与量延迟。工具输出不在 link 上流式传输。

**host 仍是三态。** `ok`、`unreachable`、`incompatible`。安装失败归 `unreachable`，说明写失败原文；构建版本或帧协议版本不符归 `incompatible`。日志方面 `executor` 只写标准错误，由 `agent` 并入自己的日志并标注 host 名，host 上不留日志文件。

**断链即失败。** link 断开时，正在等结果的 run 立即以 `host_unreachable` 结束，该工具调用写「结果未知」，队列继续。`executor` 在标准输入收到 EOF 时杀掉自己启动的全部进程组，然后退出。

**状态集中。** host 表进入 `agent` 的 SQLite。客户端只有一条事件流、一个游标与一份状态，URL 变成 `#/s/<session_id>`。广播序号、回放窗口、按节点分片、合并 bootstrap 与节点作用域转发全部删除。

**不迁移旧数据。** 新的 `agent` 从空库开始，旧库原样留在原处。

**测试不新增 seam。** 工具行为经 `agent` 的 HTTP 与文件副作用断言，测试内的传输一律是本地子进程。浏览器 e2e 同样只用本机传输。SSH 传输与安装推送只走手工验证：在开发机上以 `ssh localhost` 为 host 跑一遍注册、安装、一个工具调用与一次断链。

## 备选

- **保留 `agent` 二进制名并缩小为工具服务**：改动面最小，但「agent」一词此后指工具执行者，与规格里 agent 循环的含义直接冲突。
- **端口转发加现有 HTTP/SSE 协议**：可以复用现有路由，但远端要监听端口，等于多一层网络跳与一类端口冲突。
- **只推送本机构建的二进制**：不需要构建矩阵，但 macOS 笔记本连 Linux 服务器这种最常见的组合直接不可用。
- **断链后保持 run 在 running 并重连重跑**：抖动不丢 run，但 run 会长时间停在 running，而重跑前还要判断幂等标记与对端进程是否还活着。
- **保留按节点分片与带机器前缀的 URL**：为将来多个 `agent` 留位，但此刻没有对象，等于为一套假想的将来付账。
- **一次性导入旧库**：保住历史，但多一条只能跑一次的代码路径与它自己的测试。
- **新增 `executor` 帧协议 seam 或真实 sshd seam**：帧的每种形态都能直接断言，但同一行为于是有两套测试，且 sshd 的可失败面来自环境而不是本仓库。

## 后果

- 模型密钥与 provider 配置只存在于 `agent` 一处；host 不需要模型配置，也不需要出站网络。
- 一次 run 的工具调用固定走 session 所属 workspace 的 host。跨 host 的工具调用不存在。
- 一个 host 一条 link，多个 session 共用一个 SSH 连接，请求按 id 多路复用。
- 代码尚未实现。`docs/glossary.md` 已按新形状改写，因此在实现落地前与当前代码不一致。
- `hub` 的节点表、总线、回放窗口与客户端分片代码全部删除，删掉的代码多于新写的代码。
- `executor` 被杀而 `agent` 仍在时，远端子进程可能残留，与今天进程被强杀的情形相同。
- 术语表里的 host_updated、host_unavailable、host_unreachable 与 ssh 暂不加反引号：`scripts/check-glossary.sh` 要求反引号术语在代码里存在，实现落地时补回。
