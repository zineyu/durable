# ADR 0054: 错误分类不再复制一份无载荷枚举

- 状态：已接受。细化 ADR 0043 的分类形状
- 日期：2026-11-02

## 背景

ADR 0043 定下两层分类：`StoreError` 给出无载荷的分类，分类再给出结局类别，状态码只由结局类别决定。

实现时把「无载荷的分类」写成第二个枚举 `StoreErrorKind`，与 `StoreError` 一一对应。核对后的事实：

- 十九个变体一对一复制，`StoreError::kind` 是十九个分支的机械映射。
- 生产代码只有一个调用点：HTTP 错误信封用 `kind()` 取分类，再用 `error.to_string()` 取消息。
- `from_kind(kind, message)` 从来没有被一条非 `error.to_string()` 的消息调用过。载荷擦除因此没有换来任何调用方。
- 下游两条匹配都穷尽：`kind.class()` 到状态码，`code_of(kind)` 到协议码。`crates/core` 的测试再写一张十九行的表核对 `kind` 与 `class` 的对应，等于让映射核对自身。

结果是三个平行枚举（`StoreError`、`StoreErrorKind`、`ErrorCode`）与四条穷尽匹配，其中一条不携带任何判断。

## 决策

**取消 `StoreErrorKind`**。分类与结局类别都由 `StoreError` 直接回答：

- `StoreError::class()` 匹配十九个带载荷变体，给出五种结局类别之一：不存在、冲突、参数无效、内部、存储不可用。
- HTTP 错误信封的 `code_of(&StoreError)` 同样匹配十九个带载荷变体，给出协议码。

保留 ADR 0043 的实质决定：错误分类归内核，状态码只由结局类别决定，两个 seam 穷尽映射协议码。改变的只是分类的表达方式：从「复制一份无载荷枚举」改为「在同一个枚举上直接判定」。

## 后果

- 枚举从三个减到两个，一条十九行的机械映射与一张十九行的自反测试表消失。
- 新增 `StoreError` 变体时，编译器仍在两处要求作者表态：结局类别与协议码。表态点没有减少。
- 若将来出现「需要在不持有错误值的情况下传递分类」的调用方，再引入无载荷枚举。当前没有这样的调用方。

## 备选

- **保留 `StoreErrorKind` 并让它承担更多**：需要一个把分类当值传递的调用方，当前不存在，属于为想象中的需求付代价。
- **把结局类别直接并入 `ErrorCode`**：协议码属于对外协议，内核不应当知道它；这会把 `durable` 与客户端契约绑在一起。
