# ADR 0045: 消息树成为独立 module

- 状态：已接受。细化 ADR 0036 的压缩消息截断与 ADR 0038 的骨架读取
- 日期：2026-10-26

## 背景

消息树是本仓库被问得最多的概念。术语表为它定义了 `transcript`、`branch`、`active leaf` 与压缩消息，但它没有 module：同一个回溯被回答四次，每次的排序契约不同。

- SQL 递归 CTE 回答 transcript。顺序是「回溯深度倒序」，因为迁移 0006 改挂过父指针，id 顺序不再等于链上顺序。这条契约只写在文档注释里。
- `store` 内的四个 slice 扫描函数回答节点查找、用户祖先、子树叶子与后代判定。子树叶子的代价是 O(n²·深度)：对每个节点调一次后代判定，而后者每步线性查找父节点。
- 客户端派生层自行遍历父链与兄弟表。
- 集成测试自写父链遍历。

跨 seam 的泄漏有两处。`chain_tail` 对 transcript 做位置访问。`layout_pending_steers` 再写一遍祖先查找，并依赖同一顺序。

后果是改动回溯语义需要同时改 SQL、Rust 与测试，任何一处不改都不报错。

## 决策

**消息树是领域类型 `MessageTree`。** 它从 session 的全部消息骨架一次建立「id 到节点」与「父节点到子节点」两张索引，对外只回答树的问题：`transcript`、`leaf_of`、`ancestor`，加结构读法 `get` 与 `children_of`。树不持有 active leaf：active leaf 属于 session，由调用方传入。

**存储只返回行，不定义链上顺序。** 存储侧的递归 CTE 与「按回溯深度倒序」删除，改为按 session 取全部骨架。链上顺序、压缩消息截断与叶子选择全部由 `MessageTree` 回答，迁移 0006 的形状因此只由一处保证。

存储仍然按消息 id 升序返回行，因为块正文要按消息分组。这个顺序只服务于分组，是存储的内部细节；调用方不得据此推导链上顺序。

**索引只活在一次查询内。** 不跨查询缓存，因此没有失效逻辑。代价是 `Store::transcript` 从「只取链上的行」变为「载全部骨架再截出链」，engine 每一步多载一次骨架。接受这个代价：骨架每行只有 id、父指针、角色、run 关联与时间，远小于随后那次模型请求；正文仍只按链上的 id 取。真正的取舍是「一处实现」与「最少行数」不能同时取得。

**断链容忍。** 父指针指向不存在的节点时，该节点当作根，`transcript` 在此截断，构造索引时记一条告警。读路径不因为一条坏指针让整个 session 无法续跑。行为由单元测试固定，不靠注释。

**协议快照改名 `SessionTreeSnapshot`。** 原 `SessionTree` 不含树的任何结构，只含节点清单、队列与 run。本次让「树」只有一处实现，名字随之对齐。类型名不落在 JSON 上，路由保持不变。

**客户端本次不接入。** 客户端派生层回答的是渲染链与兄弟序，与树的问题不是同一职责；跨语言共用逻辑留给客户端视图模型那条 issue。

## 备选

- **树按查询构建，不建索引**：只收拢位置，不改变复杂度，子树叶子仍是 O(n²·深度)。
- **两个构造函数，transcript 走链上的行**：省下每一步的全量骨架载入，但压缩截断要么留在 SQL，要么在两条路径各写一次。
- **索引跨查询缓存**：省一次扫描，但引入失效逻辑，而写路径每次提交都会改树。
- **断链报 `CorruptedData`**：数据损坏应当显式报错，但代价是一条坏指针让 session 无法续跑。续跑路径的可用性优先。
- **加 `siblings`**：Rust 侧没有调用方，兄弟序只服务于客户端渲染，等客户端视图模型那条 issue 再定。

## 后果

- **`MessageTree` 是唯一回答树问题的类型。** `store` 的写命令、engine 的续跑推导与集成测试都经过它；`storage` 不再有回溯查询。
- **`Store::transcript` 每一步多载一次全量骨架。** 读方法签名不变，代价记在上面；若将来骨架行数成为瓶颈，先改存储侧的投影列，不把顺序搬回 SQL。
- **祖先查找的作用域从链改为全树。** 插话重排原先只在压缩截断后的链上找祖先，现在在整棵树上找。链本身就是从叶子到压缩消息的祖先路径，插话节点总在链尾附近，因此两者在现有调用点等价。
- **协议快照改名牵动了生成物与客户端引用。** `durable-typegen` 已重跑，`docs/api/types.md` 与 `client/src/api/generated/` 一并变更，JSON 与路由不变。
- **插话重排从扫链改为看子节点。** 找「插话在链上的那个子节点」由「遍历整条链」改为「遍历它的直接子节点并筛出在链上的那些」，代价从链长降为子节点数。
- **`MessageTree` 不是协议类型。** 它不进 `ts-rs` 导出，客户端仍用自己的派生层；两条实现的分歧由各自测试约束，不靠共享用例。
