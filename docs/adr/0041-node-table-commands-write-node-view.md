# ADR 0041: 节点表命令可以写节点视图

- 状态：已接受。细化 ADR 0028 的状态归属
- 日期：2026-11-28

## 背景

ADR 0028 决定节点状态的唯一写入者是总线 watcher：一个浏览器请求失败不构成「上游事件流是否通」的证据。本轮的节点运维增加了停用与启用。

停用后不再建立上游流，因此没有 watcher 可以写「已停用」这条状态。若只在 `NodeSnapshot` 里按 `enabled` 派生说明，客户端要合并两个状态来源；若让 watcher 每次探测前读数据库的启用标志，停用命令仍要等一个探测周期才显示生效，并且 watcher 的探测结果与命令的意图可能短暂冲突。

## 决策

把节点视图的写入权拆成两类：

- **探测结果只由 watcher 写。** 健康检查、协议版本与事件流失败仍然只能由 watcher 转成视图，与 ADR 0028 一致。
- **管理状态由节点表命令写。** 停用写 `unreachable` 与「节点已停用」；启用或修改 URL 写 `unreachable` 与「正在建立上游连接」。两者共用同一视图与同一条 `node_status_changed` 广播，客户端不需要第二个状态来源。

手动重连不写视图：它不改变节点的意图，只让下一次探测立即发生，由探测结果决定状态。

## 备选

- **停用状态由 `NodeSnapshot` 的 `enabled` 派生**：协议里多一个必须与 `status` 同步解释的字段，所有读取方都要重复合并规则。
- **watcher 每次探测前读数据库**：多一次读，且停用命令要等下一次探测才显示生效，与「停用立即停止重连」的验收冲突。
- **独立的管理状态字段与事件**：多一套状态机，与既有 `node_status_changed` 的消费方重复。

## 后果

- ADR 0028 的「状态唯一写入者」收窄为「探测结果的唯一写入者」。
- 停用与启用立即反映到视图与命令：停用后的节点作用域命令返回 `node_unavailable`。
- 启用与改 URL 会短暂显示「正在建立上游连接」，这段时间命令返回 `node_unavailable`，直到 watcher 探测成功。
