# ADR 0061: 工具与 run 的耗时只测一处并落在已有的位置上

- 状态：已接受。细化 ADR 0019 的工具节点与 ADR 0014 的 run 记录；补充 ADR 0042 的元数据约定与 ADR 0053 的单一基线规矩
- 日期：2026-11-03

## 背景

用户要看每一步用了多久，要看一次 run 用了多久，重启之后仍要对得上账，并且耗时不能受系统时间调整影响。当前只有 `bash` 把耗时写进结果正文（规格 user story A-29），其余三个工具没有耗时，tool 节点与 run 也没有承载耗时的字段。

两条既有事实决定了位置：

- 工具节点在执行之前入树（ADR 0019），因此它的 `created_at` 就是这次调用的执行起点。
- run 的 `updated_at` 只由结束路径写入；`update_run_progress` 明确不推进它，因此已结束的 run 的 `updated_at` 就是结束时刻。

## 决策

**一、耗时只测一处，测在 agent 的调用点。** `engine/tools.rs` 在 `ToolBox::execute` 前后各取一次单调时钟。`ToolBox` 与 `ToolEnd` 的形状一个字不改（ADR 0052），替身执行端也不需要跟着改。四个工具因此共用同一个测量点；改变的不再是帧协议，已安装的远端 executor 不失效。

**二、工具耗时属于「结束」这个状态。** `ToolResultState::Finished` 带必填的 `duration_ms`。`Running` 与 `Unknown` 在类型上无法携带耗时：`Unknown` 表示我们丢失了观测，此时给出一个数就是凭空造数。`ToolOutcome` 不变，帧载荷因此不变。

**三、工具耗时不需要新的列。** `ToolResultState` 本来就整体序列化进块的正文，加一个字段不动表结构。tool 节点的起点是 `message.created_at`，终点由起点加上耗时得到。

**四、run 耗时折进单一基线。** `run` 表加可空的 `duration_ms`。按 ADR 0053 的规矩，schema 变更折进单一基线，旧库由 `verify_baseline` 拒绝。可空的唯一原因是重启时被判失败的 run 没有观测到结束，它写空值，界面不显示。结束时刻不新增列：已结束的 run 的 `updated_at` 就是结束时刻，这条规则写在 `RunRecord` 上。

**五、给模型和给用户的两个数分开定名。** `bash` 正文的「耗时」行保留，规格 A-29 与 executor 的断言都不动。它是命令耗时，只覆盖命令本身；卡片上显示的是工具耗时，包含 link 往返。两者在 SSH 传输下差额明显，它们不是同一个数，也不是错误。

**六、耗时挂在产生它的东西上。** 工具卡片显示工具耗时。run 的耗时挂在该 run 在 transcript 上的收尾 assistant 消息上，悬停给出结束时刻，导出文本写同一句。没有收尾消息的 run 不显示耗时。进行中的 run 不做实时计时，界面里没有定时器。

**七、不递增协议版本。** 两处新增都是加法：旧读取方忽略不认识的字段，读到的仍是原来的值。过去几次递增都是因为旧页面会渲染出错误内容。

## 备选

- **在 executor 的工具实现里测量**：只覆盖纯执行时间，但要改帧载荷并递增协议版本，全部远端 host 变 `incompatible` 并需要重装 executor。我们选择包含传输时间的端到端数字，因为用户问的是「这一步等了多久」。
- **让 `ToolEnd` 带耗时**：耗时与结局一次返回，但改掉 ADR 0052 定下的两支契约，替身执行端也要跟着改；调用点测量得到同样的数。
- **把耗时放到 `ContentPart::ToolResult` 上作为可空字段**：`Running` 与 `Unknown` 因此也能写出耗时，类型允许无意义的状态。
- **run 加 `ended_at` 列**：与 `updated_at` 在每一条写入路径上都相等，等于给同一个事实起两个名字。
- **run 耗时取 `updated_at - created_at`，不动 schema**：零迁移，但系统时间被调整时这个数就错，「不受系统时间调整影响」对 run 不成立。
- **首次引入增量迁移 `0002`**：保留旧库，但要放宽 `verify_baseline`，推翻 ADR 0053 明确写下的「没有增量迁移路径」。
- **删掉 executor 的耗时行，改由 prompt 装配把测得的耗时写进发给模型的正文**：全局只有一个数，代价是模型看到的正文与落库正文不一致，且要改请求装配。

## 后果

- 旧数据库不再能打开，现存历史全部作废。提交信息标记 `BREAKING CHANGE:`。
- 生成物要重跑 `durable-typegen`：`client/src/api/generated/` 与 `docs/api/types.md` 一并提交。
- 工具耗时与命令耗时的差额等于 link 与调度开销。这两个术语在 `docs/glossary.md` 里分工，界面只显示前者。
- 崩溃恢复的 run 在界面上没有耗时，与工具侧「结果未知」的处理一致。
- 按工具名汇总的统计不在本决定内。
