# ADR 0031: 供应商限流用独立失败类别并有限重试

- 状态：已接受。细化 ADR 0014 的失败类别与 ADR 0018 的实时事件
- 日期：2026-10-21

## 背景

ADR 0023 删除并发槽位后，session 之间没有并发上限。多 session 同时跑时，一次 `429` 就让整条 run 失败；`RunFailureCode` 把限流与「供应商返回 500」混成同一个 `ModelUpstream`，客户端无从判断「等一会就好」与「上游坏了」。`provider` 不读状态码语义，也不读 `Retry-After`；`engine` 没有重试路径。

## 决策

- **稳定类别 `model_rate_limited`。** 判定依据是 HTTP `429`，或响应带 `Retry-After` 头。其余非 2xx 仍是 `model_upstream`。
- **`provider` 上报，`engine` 决策。** `provider` 把状态码、正文与 `Retry-After`（秒数形式）放进错误；HTTP 日期形式不支持，按没有建议处理。`engine` 决定是否重试与等多久。
- **重试在单次模型调用内部完成。** 不重起 run，不改队列与取消语义。默认 3 次，指数退避，底数默认 1000 毫秒，单次等待上限 30 秒；有 `Retry-After` 时以它为准。配置项：`DURABLE_MODEL_RETRY_LIMIT`（`0` 表示不重试）、`DURABLE_MODEL_RETRY_BACKOFF_MS`。
- **重试只发实时提示，不写事实。** 等待前发一条 `retry` 事件，携带重试序号、上限与等待时长。它不落库、不推进游标、不进回放窗口；`hub` 原样转发并补上节点名。
- **取消优先于重试。** 请求与等待都可被取消打断；等待中取消时 run 以 `cancelled` 结束，不再重试。
- **耗尽后失败。** run 以 `model_rate_limited` 结束，说明里带供应商建议的等待时长；队列继续下一项。
- **不引入全局并发上限、跨 run 共享限流器或模型回退。** 限流只由供应商自然施加。

## 备选

- **只加类别不重试**：短促的 `429` 照样作废整条 run，用户须手动重发，等于把成本转给人。
- **把重试写成事实事件**：重试是易失的运行时状态，刷新后不该被重放；写库还会污染游标语义与回放窗口。
- **重试整条 run**：run 生命周期、队列位置与取消语义随之复杂，收益不足以抵消。

## 后果

- 客户端能显示「正在重试」；该提示刷新即消失，这是有意的：它不是历史。
- 重试期间 run 仍是 `running`，取消按钮保持可用。
- 新实时事件进入 `agent` 与 `hub` 的事件流，因此 `agent` 协议版本升到 2，`hub` 期望的 agent 版本与自己的浏览器协议版本同步升到 2。混跑旧版会得到 `incompatible`，而不是静默丢弃提示。
