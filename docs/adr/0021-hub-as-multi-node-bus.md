# ADR 0021: hub 作为多节点总线

- 状态：已接受
- 日期：2026-11-03

## 背景

用户在多台自有机器上各运行一个 `agent`。权威状态按机器分开，每个 `agent` 持有自己的 SQLite、事件序号与游标。原 `ui` 是单 `agent` 的直通代理：一个 `--agent-url`，`/api/*` 原样反代，不做聚合。用户要在一个页面里切换与管理全部机器，并要求多个客户端经同一入口并发读写。

## 决策

`ui` 重命名为 `hub`，并从直通代理升级为总线：

- **节点表属于 hub**。`hub` 有自己的 SQLite，只存 `node` 表。`hub` 不存 session、消息、队列、run 或事件。
- **协议合并**。浏览器只面对 `hub`。聚合端点 `/api/bootstrap`、`/api/events`、`/api/nodes` 由 `hub` 提供；节点作用域用路径前缀 `/api/n/<node>/...`，`hub` 剥掉前缀后原样转发。
- **合并 bootstrap 尽力而为**。一个节点失败只体现在它自己的 `status` 里，HTTP 仍 200。
- **hub 是总线**。`hub` 为每个可达节点常驻一条上游事件流，指数退避重连，并向全部客户端广播。
- **广播序号**。`hub` 给每条广播事实信封赋自增序号，并保一个内存有界回放窗口。客户端游标是 `hub` 的序号：窗口内回放，窗口外要求 resync。`hub` 重启后窗口为空，全部客户端 resync。
- **慢客户端隔离**。每个客户端一个有界发送队列，溢出即关闭该客户端的事件流，由其重连后 resync。
- **版本握手**。`/api/health` 带协议版本。不匹配的节点状态为 `incompatible`。
- **`hub` 自身的事实事件走同一条流**。`node_registered`、`node_removed`、`node_status_changed` 带 `hub_seq`、不带 `node` 字段。节点表的变更因此对所有已打开的客户端立即可见。

## 备选

- **纯路由**：逐节点命名空间加逐节点事件流，`hub` 不解释协议。改动最小，但客户端要维持 N 条流与 N 个游标，侧栏要自己做 fan-out。
- **向量游标**：游标是每节点水位，`hub` 无需缓冲。但客户端重连时 `hub` 要为单个客户端重开 N 条上游流取回放，合并出现两条路径。
- **`hub` 级 id 持久化**：`hub` 把序号映射落库，重启后仍能回放。多一套持久状态，且与「权威状态在 node」冲突。
- **浏览器直连节点**：从原协议不满足同源，且要 CORS 与多地址。

## 后果

- 事实事件跨节点没有全局顺序。顺序只在单个 node 内成立。客户端不得依赖跨节点因果。
- `hub` 不持久化广播状态，所以重启代价是全量 resync，而不是回放。
- `hub` 重启不影响任何 run：run 在 node 上执行。
- 事件归于 node 的 SQLite，`hub` 删除或重建不损失领域数据。
- 上游重连与广播编号是 `hub` 唯一的状态机，成为新的测试 seam。
