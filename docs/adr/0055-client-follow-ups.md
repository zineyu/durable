# ADR 0055: 客户端收尾：滚动恢复、不可用 host 的说明与连接状态升级

- 状态：已接受。细化 ADR 0048 的客户端部分与 ADR 0017 的派生视图接线
- 日期：2026-11-03

## 背景

host 反转落地后，规格 `remote-ssh-process-model.md` 的四个验收点只做到一部分：

- R-45 要求刷新后恢复选中 session 与滚动位置。选中位置已由 URL 哈希与 `durable:last-session` 恢复，transcript 的滚动位置没有任何记录，刷新后总是回到顶部。
- R-47 要求不可达 host 的会话列表为空并给出说明。派生层已把这类 workspace 的 session 清空，但侧栏只在选中该 host 的 session 时才显示说明；什么都没选时只剩「暂无 session」，容易被读成「没有会话」。
- R-19 要求不可用 host 的 workspace 与 session 不可操作。页脚的发送按钮与主面板已按 host 可用性禁用，侧栏的新建 session、移除 workspace 与 host 面板的改名、删除仍可点击。注册 workspace 对话框还把 host 默认值写成字面量 `local`。
- R-49 要求连接状态显式可见。事件流断开后重连循环没有升级条件：只有首次 bootstrap 失败显示「已断开」，此后一直停在「重连中」，即使 agent 长时间不在线。

## 决策

**滚动位置按 session 记在浏览器存储里，键为 `durable:scroll:<session_id>`。** 记录取整数像素，回到顶部时删除记录。读取与写入收进 `view/scroll.ts`，以存储接口为参数，因此可以用内存实现直接断言。

**恢复在每次渲染后重试，直到达成或用户自己滚动。** 正文异步到达，内容高度会增长；只在挂载时设一次 `scrollTop` 会被当时的高度截断。`view/use-transcript-scroll.ts` 在布局阶段把位置设为目标值，记录浏览器实际接受的值，未达成时在下一次提交后再试。滚动事件与上一次实际值相差不足 1 像素时视为程序滚动，不写存储；否则视为用户滚动，写入并结束恢复。`SessionPane` 已按 session 加 `key`，切 session 即重挂载，状态不跨 session 泄漏。

**不可用说明落在 workspace 的派生视图上。** `WorkspaceSummary` 新增 `notice`：host 可用时为 `null`，不可用时取 host 的说明，host 不在表里时取「未知 host」的固定文案。侧栏据此在会话位置显示说明，不再有整块替换列表的全局提示。判定仍只有 `hostViewOf` 一处。

**禁用范围是依赖 host 可用的写操作。** host 不在 `ok` 时禁用：workspace 的新建 session 与移除、host 面板的重命名与删除。保留「停用/启用」与「重连」：停用过的 host 必须能重新启用，重连正是从不可达恢复的手段。禁用状态由派生层的 `available` 决定，说明文本由 `notice` 给出，组件不重新判断可用性。

**注册 workspace 的默认 host 跟着当前选中位置。** 有选中 session 时取其 host；否则取第一个可用 host；否则取 host 表第一项；都没有时为空串，由确认按钮的非空校验拦住。这条规则是 `derived.ts` 的纯函数 `defaultWorkspaceHost`。

**连接状态在连续 3 次重连失败后升级为「已断开」。** 重连等待是 1 秒，因此故障约 3 秒后可见。计数与判定收进 `view/connection.ts`：进度记连续失败次数与「本次页面运行里是否连上过」，成功打开归零并回到「已连接」，失败累计，达到阈值即「已断开」。首次 bootstrap 失败立即显示「已断开」，进度保持「未连上」，随后的失败不会把状态降回「重连中」。首次失败与断线重连走同一条等待快照的循环，拿到快照后开流，因此 agent 恢复后无需刷新即可回到「已连接」。

## 备选

- **把滚动位置放进客户端状态或 URL**：状态与 URL 都要在刷新时重建，而浏览器存储本来就是这类界面偏好的落点；放进状态还会让每次滚动触发一次 reducer 归约。
- **用 `scrollHeight - scrollTop` 记录离底距离**：聊天界面常用，但规格说的是滚动位置，且内容高度在正文到达前不可信。
- **恢复只做一次，等树与正文都到齐**：需要给面板加一个「内容已就绪」的信号，多一条跨模块时序；按提交重试没有新增信号。
- **侧栏保留全局提示，另加每条 workspace 的说明**：同一事实两处渲染，选中与未选中时文案来源不同，容易漂移。
- **host 面板全部写操作禁用**：与验收字面一致，但停用过的 host 无法再启用，形成死路。
- **用时间阈值替代失败次数**：需要引入时钟与定时器，纯函数变成带时间的函数；1 秒固定等待下次数与时间等价。
- **把升级条件放进 reducer，用动作累计失败**：reducer 已经用 `connection` 动作接收状态；把网络尝试的计数搬进领域状态会让事实流多一类只与本地网络有关的字段。

## 后果

- 刷新后 transcript 回到离开时的位置；同一浏览器里每个 session 各有一份。
- 侧栏在任何选中状态下都能指出不可达 host 的原因，且该 host 的会话确实不在列表里。
- 不可用 host 的写操作在界面上不可发出，服务端的 `host_unavailable` 仍是最后一道判定。
- agent 长时间离线时用户能看到「已断开」，恢复后自动回到「已连接」。
- 新增测试：`view/scroll.test.ts`、`view/connection.test.ts`、`derived.test.ts` 的说明与默认 host 用例；e2e 新增 `scroll.spec.ts` 与 `host-availability.spec.ts`，`reconnect.spec.ts` 增加升级与恢复用例。
- 浏览器存储多一类键；用户清除站点数据会同时丢失草稿、上次 session 与滚动位置。
