# ADR 0022: 节点名即身份

- 状态：已接受
- 日期：2026-11-03

## 背景

`session_id` 由各 node 的 SQLite 产生，跨 node 不唯一。URL 要能直达一个 session，因此 URL 必须携带节点。三种做法：用节点名做键、`hub` 分配稳定 id、`hub` 生成全局 session id。

## 决策

节点名就是节点身份。URL 形如 `#/n/<node>/s/<session_id>`，全局 session 键为 `(node, session_id)`。

- 注册时校验名称非空、唯一、URL 非空。不校验可达性。
- 名称可以改。改名后旧 URL 失效，页面显示「未知节点」。
- `hub` 不存 id 映射表，也不生成全局 session id。

## 备选

- **`hub` 分配稳定 id**：改名不影响链接，但多一个不可见的身份字段，节点名降级为展示文本。
- **`hub` 生成全局 session id**：客户端只见一个 id，但 `hub` 要持久化映射，破坏「`hub` 不存领域状态」。

## 后果

- URL 可读，代价是改名会破链接。这是用户明确接受的取舍。
- 路径前缀 `/api/n/<node>/...` 与 URL 使用同一身份，转发规则机械且唯一，`hub` 无需反查。
- 与 `workspace` 一致：身份由用户给定的键承担，不是系统生成的 id。
- 未知节点必须有显式页面状态，不能落成空白或 404 错误页。
