# ADR 0059: 超时离开副作用库

- 状态：已接受。推翻 #79 契约中的「上界」与「超时终态」两项；补充 ADR 0037 的崩溃恢复与 ADR 0031 的限流重试预算
- 日期：2026-11-04

## 背景

`#79` 的契约把 `bound`（每类的上界）、`on_timeout`（超时终态）与 `Terminal` 放进类别表，并让 `perform` 用 `tokio::time::timeout` 包住工作体。它的理由是「liveness 的唯一来源」。第一个消费者 `#80` 尚未接线，因此此刻改这个接口的代价最低。

把上界交给这张表有三个问题。

第一，兜底变成了主手段。今天 provider 请求没有客户端超时（`reqwest::Client::new()`），link 请求没有截止时间（`#65`），于是「600s 后放弃」成了唯一能让悬挂 run 收敛的东西。一个不认识介质的数值被迫承担主要职责，而它回答不了「这条链路是死了还是只是慢」。

第二，库因此依赖运行时。`effects` 不做 I/O、不碰网络、不起进程，只为计时引入了 `tokio`。

第三，超时终态把两件不相干的事混在一起：模型与压缩超时要落成 run 的失败码，四个工具超时要落成工具节点的「结果未知」。类别表于是被迫知道业务的收尾方式，而 `#79` 的另一条原则正是「库不知道结局在业务上是什么意思」。

## 决策

**从 `Effect` 删除 `bound`、`on_timeout` 与 `type Failure`，删除 `Terminal`。** 类别表的表态从五项降到三项：`name`、`replay`、`matrix_scope`；`const ALL` 仍是唯一清单。

**`perform` 不再包超时。** 它只做「执行工作体、写结局、返回结论」；工作体自己决定何时放弃，并可以用 `Lost(Timeout)` 报告放弃。

**保留 `Lost::Timeout`。** 库不产生它，只承载它。介质层判定超时后上报，写库与恢复因此仍能区分「链路没了」与「链路还在，但我们不再等」。

**超时归各介质层。** provider 请求的客户端超时在 `#82` 接线时加；link 请求的截止时间在 `#65`；`bash` 的内部 120s 已有。

**`effects` 不再依赖 `tokio`。** `deps.allow` 的 `effects tokio` 一并删除。

## 备选

- **库内上界（原契约）**：一处能看到「每类多久算太久」。代价是上面三条，而且数值与介质无关。
- **`effects` 不管，`core` 保留一张每类上界表**：位置换了，缺陷相同；那张表同样不认识介质。
- **完全不设自动上界，只靠取消信号收敛**：用户没点取消、心跳正常而请求挂住时，run 永远不会结束。
- **连 `Lost::Timeout` 一起删掉**：介质层的截止时间要么被说成断链，要么自造一套结局类型。`#81` 的恢复会把「可能跑过、链路仍好」误当成「宿主已丢」。

## 后果

- 「悬挂的 run 会收敛」从库的保证降级为各介质各自的保证。`#65` 与 provider 超时因此从「后续改进」变成 `#82` 的前置条件，用户可见的收敛时间由介质层决定。
- `#80` 的验收原文写「名字 / 上界 / 重放 / 超时终态 / 覆盖声明」，需要改为三项表态。
- 公开 API 少三个成员并删除一个类型。没有第三处代码在适配旧签名。
