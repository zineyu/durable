# ADR 0038: 事件与快照只带骨架，正文按需拉取

- 状态：已接受
- 日期：2026-10-22
- 状态说明：取代 ADR 0019 的 `tool_call_recorded`

## 背景

原来的 `message_appended`、`message_updated` 事件携带整条消息，而事件又要落进 `event` 表。ADR 0035 让消息存下完整内容（推理、工具结果、图像），一份 256 KiB 的读文件结果会在库里出现两次，每次重连回放也要重新推一遍；session 树快照则会把整棵树连正文一起发给浏览器。

## 决策

**事实事件与快照只描述结构**。节点骨架包含 id、parent、role、run、时间，以及每个块的 `seq`、`kind`、字节数与状态，不含块正文。

**正文按消息 id 批量拉取**：新增一个读接口，接收消息 id 列表并返回块正文。客户端按消息 id 缓存正文，渲染到哪条取哪条。

**进行中的内容用未来会定型的消息 id 作键**。assistant 消息在定型前不入树（ADR 0037），但它的 id 在该步开始时就从全局分配器铸造。增量事件携带这个 id，客户端为它建立本地占位节点；`message_appended` 到达时用同一个 id 覆盖占位。崩溃或 run 结束时，客户端丢弃仍未定型的占位。

**工具节点的状态变化用 `message_updated` 表达**：执行中入树时发 `message_appended`，写入结局时发 `message_updated`。原 `tool_call_recorded` 事件删除，它的职责由这两条事件与 tool 节点承担。

## 后果

- 事件表不再重复存历史正文，回放与重连的开销与会话内容量脱钩。
- 契约只有一条：事件说「变了」，正文从读接口取。客户端必须处理「骨架已到、正文未到」的中间态，渲染要有占位。
- resync 之后客户端要补齐缺失的正文；已缓存的正文在 `message_updated` 后按消息 id 失效。
- 需要一条「正文缓存」的约束：按消息 id 缓存，不按节点位置缓存，因为分支切换会复用同一条消息。
- 多一条 HTTP 读接口与它的测试；`durable-e2e` 要覆盖「刷新页面后正文补齐」。
