# ADR 0028: 节点作用域转发的超时与状态归属

- 状态：已接受
- 日期：2026-11-20

## 背景

`hub` 把 `/api/n/<node>/*` 剥掉前缀后原样转发给 node，用同一个 `reqwest::Client`，不设任何超时。当 `agent` 进程被挂起（TCP 未断、不响应）时，浏览器的命令请求永久挂起，而节点状态仍是 `ok`。要修这条路径，得同时回答两个问题：转发失败是否改写节点状态，以及怎样在不认识 agent 端点清单的前提下区分"命令"与"流"。

## 决策

**节点状态的唯一写入者是总线 watcher。** 转发失败只改变该次请求的结果（`node_unavailable`），不改写节点状态。理由是状态的语义是"该 node 的上游事件流是否通"，一个浏览器的一次失败请求不构成证据。卡死的 node 由 watcher 的流空闲超时降级，因此转发路径不必代劳。

**按响应类型分档超时，不按路径。** `hub` 继续不认识 agent 的端点清单：

- 连接超时 5 秒。
- 发送阶段（含等待响应头）受命令总截止时间约束，30 秒。
- 拿到响应头后，`content-type: text/event-stream` 的响应转为逐块空闲超时，45 秒；其他响应继续用同一个 30 秒总截止时间读完 body。
- 超时映射为 `node_unavailable`，说明里写明"命令超时"或"事件流空闲超时"。

三个时长都是 `hub::HubOptions` 的字段。测试注入小值，不引入环境变量。

## 备选

- **转发失败即降级节点**：省掉一次重复超时，但单次瞬时失败（慢 body、大上传）会误判整个节点，且需要第二套"谁有权改回 `ok`"的规则。
- **按路径判定 `/events` 是流**：实现更直接，但 `hub` 从此内置 agent 的端点清单，将来 agent 新增流式端点必须同步改 `hub`，破坏"原样转发"。
- **按请求 `Accept` 头判定**：客户端漏写就选错超时，规则漂在约定里。

## 后果

- 节点不可用的时间上界约为"流空闲超时 + 退避"，与命令超时无关。
- 一个卡死但在发 keep-alive 的 agent 不会被降级（它的流仍然活着）。这是有意的：此时命令仍能成功送达，只是慢。
- 空闲超时 45 秒等于 3 个上游 keep-alive 间隔（15 秒）。上游若缩短 keep-alive，这个值要跟着改。
- 非 SSE 响应在转发侧先读完再返回，`hub` 不再逐块转发普通响应，body 大小由上游决定。换来的是超时能映射成 `node_unavailable`，而不是一个被截断的响应。目前没有非 SSE 的流式端点。
